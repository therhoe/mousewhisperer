Onboarding sequence — what a merchant sees today

Recreation of the current first-install experience, screen by screen, taken from the code on the tooltags branch. Finding: the app has no dedicated onboarding wizard. After Shopify's own install screen, the merchant lands straight on the dashboard in its first-run state. The yellow notes flag gaps to consider in tomorrow's redesign.

Shopify App Store → Install

This screen is owned by Shopify: the merchant clicks Install on the app listing, then approves the permission grant (read products/themes, write pixels, etc.). The app cannot customize it. After approving, Shopify redirects into the embedded app — which lands directly on the Dashboard (step 2).

Gap There is no welcome screen, tour, or setup checklist between install and the dashboard. The first thing a brand-new merchant sees is an analytics dashboard with no data in it.

Gaps 1) The "Getting Started" card is now just a heading with a Dismiss button — its body copy was removed in the tooltags cleanup, so it teaches nothing. This is the natural home for a real setup checklist.
2) The most prominent card on first load is an approval-blocked analytics panel the merchant can do nothing about. Consider reordering or softening for first-run.
Rich storefront tracking Not active hero-outfitters.myshopify.com
Biggest gap in the current flow Rich tracking requires the merchant to enable the "tracking-embed" theme app embed in the theme editor — but nothing anywhere in the app tells them this or links them there. The status row just says "Not active" with a Retry button. A redesigned onboarding should deep-link to /admin/themes/current/editor?context=apps with a clear "Enable tracking" step, and verify automatically once it's on.
